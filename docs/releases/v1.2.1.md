# v1.2.1 verification

This release adds history-based attribution for lines still in use, broader language-aware line reading,
more accurate test and production classification, and the public `assets/coderprint.json` data file.
The relay accepts the new data file and keeps compatibility with older `cards.json` profiles.

## Reproducible checks

- `npm test`: 177 checks passed on Windows, with no failures or skipped checks. Linux CI exposed
  a Chrome XML-parser difference for `xml:` element names; a regression now rejects those elements
  while preserving valid `xml:` attributes.
- `python test/py/run.py`: runs the line, test-classification, history, identity, in-use, panel,
  operation, data-file, and original collection regression scripts. GitHub responses are replaced
  with fixtures; these checks do not require another GitHub account.
  All 744 checks passed locally: 715 across the nine main scripts and 29 in the recovered
  original collection harness, which was run separately before being added to the runner.
- `python test/py/main_test.py coderprint.py PATH_TO_V1_2_0/coderprint.py`: 60 checks passed,
  including the four-panel comparison with v1.2.0. The baseline must have the unchanged `design/`
  directory beside it. The comparison allows the documented language-row wording, metadata,
  and accessibility-description changes.
- A live smoke run used the existing owner's GitHub identity and only the public coderprint
  repository. It generated all panels and `coderprint/1` data, with one repository read and no
  unread histories, heads, or attributes. The light panel rendered in Edge at 576 by 445 with
  no page errors and was visually checked. No profile files were published by this smoke run.

The CI workflow runs the Node and Python suites on every push and on pull requests to `main`.
It has a 40-minute job limit, 300 seconds for Node, 1,800 seconds for Python, and 300 seconds
for each Python regression script. Local checks also ran under an external process-tree deadline.

## Real public history

Both versions collected the same public [curl history](https://github.com/curl/curl/tree/852ebe5dd1e2bc634e616afc2ecf5a00269d83b4):
39,899 commits at `852ebe5dd1e2bc634e616afc2ecf5a00269d83b4`, cloned from its default branch with full history.
Identity lookups were stubbed as an organization, so every author's eligible work could count.
This measures real Git-history processing; it is not a test of live GitHub account attribution.

| Measurement | v1.2.0 | v1.2.1 candidate |
| --- | ---: | ---: |
| Collection wall time | 55.208 s | 80.053 s |
| Peak process memory | 196.7 MB | 379.8 MB |
| Written lines | 775,946 | 691,868 |
| Lines in use | 238,013 | 252,088 |
| Traced lines in use | Not recorded | 147,119 |
| Text-matched lines in use | Not separated | 104,969 |
| Repositories without line diffs | 0 | 0 |

The candidate also reported zero unread heads and zero unread attribute sets. Its traced and
text-matched lines sum to lines in use, and lines in use do not exceed written lines. Changed
counts reflect changed counting rules; this benchmark does not independently establish the
ground truth for curl. These are single Windows measurements with other local checks running,
not an isolated performance study. Memory is the Python process's peak working set, not the
combined memory of every Git child process. The more detailed collector costs time and memory.

The measured candidate's `coderprint.py` SHA-256 is
`7b9eb91b912663b068f5638bfe99b9c69371fb3b463d1946470745b965bc78d9`.
To repeat against an existing public clone, use `tools/benchmark_history.py` with explicit
`--seconds`, `--work`, and `--output` arguments, under an external process-tree deadline.
No synthetic commits are generated by that benchmark.

## Remaining limits

- Some languages use approximate comment reading; unknown line origins use text matching.
- A retained branch and its sufficiently changed rebased copy can still count some work twice.
- Unread line diffs fall back to added-line totals for written work and contribute no lines in use.
- Organization profiles work without the relay; organization cards through the relay remain unsupported.
- A second independent GitHub account was unavailable. Its live identity scenarios were not verified;
  the identity suite uses explicit fixtures, and the smoke run used the existing owner account.

Update an older relay deployment before generating profiles that replace `cards.json` with
`coderprint.json`. The upgraded relay continues to read older profiles.
