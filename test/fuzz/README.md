# Relay input fuzzing

These two Jazzer.js targets feed coverage-guided byte mutations to the pure relay parsers in `lib/compose.js`. `svg.mjs` exercises SVG sanitizing, document parsing, compact-panel parsing, and card composition. It checks that accepted markup is stable, remains parseable, and drops event and external URL attributes. `cards.mjs` exercises both raw and syntactically valid JSON for the card settings contract and checks the returned palette and music IDs.

`properties.test.js` adds 1,000 fast-check runs with shrinkable counterexamples. Its generators build valid SVG text surrounded by unsafe attributes, valid and invalid JSON settings, and raw byte inputs fed through both parser harnesses. The two tools complement each other: fast-check explores structured inputs and minimizes failures, while Jazzer.js follows coverage feedback into parser branches.

The checked-in corpus covers ordinary SVG, scripts, unsafe URLs, style text, malformed nesting, valid settings, hostile identifiers, and truncated JSON. CI copies these seeds to a temporary corpus, replays them, then runs each coverage-guided target for 60 seconds. Generated cases stay out of the repository. The `fuzz` job runs on pushes to `main`, pull requests, weekly, and by manual dispatch; a crash or failed assertion fails the job. CI also audits the locked dependencies, failing on advisories at any severity. Installation disables package lifecycle scripts; Jazzer.js still executes the native fuzzer shipped inside its integrity-checked npm package.

To run locally, install the isolated locked dependencies with `npm ci --prefix test/fuzz --ignore-scripts`, then from `test/fuzz` run `./node_modules/.bin/jazzer ./svg.mjs --sync ./corpus/svg -- -max_total_time=60 -max_len=4096 -timeout=2` and the corresponding `cards.mjs` command with `./corpus/cards`. Run these through a process launcher with an explicit finite wall-clock deadline, and use a copy of each seed directory if you do not want Jazzer.js to add generated inputs to the checked-in corpus. `--mode=regression` replays only the supplied seeds.

The fuzzing job provides bounded testing, not proof that every SVG or JSON input is safe. OpenSSF Scorecard may take time to discover the new fuzz target and may not recognize every fuzzing framework.
